# TAKEOVER Lyric Stage

初音ミク「マジカルミライ 2026」プログラミング・コンテスト応募作品です。  
Twinfield さんの **TAKEOVER** を題材に、TextAlive App API の歌詞・拍・サビ・声量情報と Three.js の 3D ステージを同期させた、ライブ会場型のリリック PV として制作しています。

- 対象楽曲: **TAKEOVER / Twinfield** (<https://piapro.jp/t/E2i3>)
- 歌詞情報: TextAlive App API 経由で取得
- 画面演出: 3D モデル、カメラワーク、歌詞タイポグラフィ、終盤の暗転・リプレイ導線

## 作品のアピールポイント

この作品では、歌詞を字幕として読むのではなく、楽曲に「TAKEOVER されていくステージ」として体験できることを目指しました。  
TextAlive App API から取得したフレーズ、単語、文字、拍、サビ、声量を `window.MusicBG` に集約し、3D カメラ、モデルの表情、背景の光、歌詞タイポグラフィへ同時に流し込んでいます。

歌詞演出は曲の区間ごとに `SIGNAL LOST`、`SYSTEM SCAN`、`TAKEOVER`、`SIGNAL EXPANSION`、`SIGNAL ACQUIRED` という内部セクションへ分け、登場スタイルや色を切り替えています。サビではピンクと黄色の発光を強め、終盤では流れ星とフェードアウトで余韻を作り、最後にリプレイ画面へ戻る一本の映像体験としてまとめています。

見た目の派手さだけでなく、同じフレーズは同じ見た目になり、曲の構造に合わせてカメラと歌詞が変化するようにしています。ライブ映像、MV、カラオケ字幕の中間にあるような「音楽に同期して動くリリック・ステージ」が本作の核です。

## 起動方法

ビルドは不要です。リポジトリ直下を静的 HTTP サーバで配信してください。`file://` で直接 `index.html` を開くと、ブラウザの制約で TextAlive の楽曲データを取得できません。

```bash
# 例 1: PHP
php -S localhost:8080

# 例 2: Node.js
npx serve .
```

ブラウザでサーバの URL を開き、最初の画面をクリックまたは Enter/Space キーで開始します。  
本番画面では再生コントロールや HUD は表示せず、楽曲終了後に「もう一度再生」ボタンを表示します。

## 画面構成

- **スタート画面**: 楽曲と作者名を表示し、ユーザー操作で音声再生を開始します。
- **3D ステージ**: GLB モデル、床リング、星空、オーディオ風ビジュアライザ、ブルームを描画します。
- **歌詞タイポグラフィ**: フレーズ単位で大きく表示し、単語情報からキーワードを強調します。
- **リプレイ画面**: 曲の終盤演出後に暗転し、再生し直す導線を出します。

## 主な実装ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | 画面の骨格、CDN 読み込み、スタート/リプレイ画面 |
| `style.css` | 3D ステージ上に重なる歌詞 PV、開始画面、リプレイ画面のスタイル |
| `app.js` | TextAlive Player の初期化、楽曲ロード、再生状態・歌詞・拍・サビ・声量の共有 |
| `stage3d.js` | Three.js のメインステージ、GLB モデル、カメラ演出、ブルーム、床リング、流れ星 |
| `textpv.js` | フレーズごとの歌詞タイポグラフィ、variant/tone 選択、キーワード強調 |
| `lyrics3d.js` | 曲終了時の `TAKEOVER` 遠ざかり演出 |

## 同期の仕組み

`app.js` は TextAlive App API の各イベントを受け取り、次の情報を `window.MusicBG` に更新します。

- 再生位置、再生中かどうか
- 現在のフレーズ、単語、文字の開始時刻と進行度
- 拍の進行度、サビ判定、声量
- 曲構造から推定した内部セクション

`stage3d.js` と `textpv.js` はこの共有状態を読み取り、同じタイミングで別々の演出を動かします。これにより、歌詞が出る瞬間、カメラが切り替わる瞬間、光が強くなる瞬間が同じ音楽情報に結びつきます。

## 歌詞演出

歌詞はフレーズ単位で表示し、曲中の区間に応じて見た目を切り替えます。

| セクション | 意味 | 主な演出 |
| --- | --- | --- |
| `intro` / `amelo` | SIGNAL LOST | 低めの発光、スライドやタイプライター風の出現 |
| `bmelo` | SYSTEM SCAN | 縦書き、振動、ピクセル化などの探索感 |
| `chorus` | TAKEOVER | 強い発光、バースト、グリッチ、ホットカラー |
| `interlude` | SIGNAL EXPANSION | 余白を活かした反復カメラと残像 |
| `finale` | SIGNAL ACQUIRED | 流れ星、強い発光、終盤フェード |

`textpv.js` ではフレーズ本文のハッシュ値とセクションから variant と tone を決めるため、同じフレーズは毎回同じ印象になります。単語情報が取れる場合は、フレーズ内で最も意味の強い語を大きくし、声量に合わせてサビの強調が脈動します。

## 3D ステージ演出

3D 側では `3D/素体9.glb` を読み込み、`Dance` アニメーションをループ再生します。GLB に表情モーフがある場合は、声量に合わせた口の動き、まばたき、サビでの笑顔を反映します。

カメラは楽曲冒頭の固定キューとフレーズ進行を併用して切り替わります。歌詞がない間奏でもカメラが止まらないように、区間ごとに自動でショットを循環させています。

## 使用ライブラリ

- [TextAlive App API](https://developer.textalive.jp/) 0.4.0
- [Three.js](https://threejs.org/) 0.165.0
- axios 1.17.0

本番ページは CDN 読み込みのみで動作し、ビルド工程はありません。

## 動作確認

主な確認対象は Google Chrome 最新版です。  
ローカル確認では、HTTP サーバ経由で表示し、スタート画面から開始して歌詞・3D・リプレイ画面までの一連の流れを確認してください。
